# XAUUSD Signal System v6.0

Сигналы по золоту (XAUUSD), построенные строго по 12-блочному курсу трейдинга
(свечи → таймфреймы → тренд → S/R → пробой+ретест → объём → EMA → свечные
паттерны → графические фигуры → вход/SL/TP). Заменяет старую "5 фильтров
одновременно" версию — там сигнал требовал 5 случайных совпадений разом и
почти никогда не срабатывал.

Два варианта реализации — выберите один:

- **`python_bot/` (рекомендуется)** — полностью на Python, без TradingView и
  **без numpy/pandas** (чистый stdlib + requests), поэтому гарантированно
  работает на любом процессоре, включая старые CPU без SSE4.1/AVX (готовые
  сборки numpy/pandas на таком железе падают с "Illegal instruction" — сами
  на этом обожглись, поэтому от них отказались). Сам тянет котировки, сам
  считает TA, сам шлёт в Telegram. Работает бесплатно (Yahoo Finance chart
  API, без регистрации) или через демо-счёт OANDA.
- **`XAUUSD_TA_Master_v6.pine` + `webhook_relay.py`** — индикатор в
  TradingView + внешний сервис на вебхуке. **Требует платный план
  TradingView (Essential и выше)** — на бесплатном Basic вебхуки в алертах
  не работают. Оставлено как вариант, если вы всё же оформите подписку или
  захотите визуально видеть индикатор на графике TradingView.

Claude в обоих вариантах **не видит график** — только структурированные поля
сетапа (тренд/уровень/тип/объём/фигура), которые уже посчитала TA-логика. Это
доп.проверка на внутренние противоречия (например "двойная вершина" при
LONG), а не независимый визуальный анализ. Реалистичная цель для системы на
классическом TA — 40-55% винрейт при R:R около 1:2 (прибыльно при
дисциплинированном риск-менеджменте) — 75-85% не гарантирует ни один код.

**Перед тем как доверять сигналам деньгами: минимум 2-4 недели вести
бумажный журнал (Блоки 11-12 курса) и сверять сигналы с тем, что вы видите на
графике вручную.**

## Вариант А: python_bot/ (без TradingView, рекомендуется)

### Как бот "видит" график золота

Никакого TradingView не нужно — бот сам скачивает свечи (H4/H1/M15) из
одного из двух источников (`data_sources.py`):

- **Yahoo Finance** (по умолчанию, `DATA_SOURCE=yahoo`) — без регистрации,
  работает сразу, напрямую через `requests` (без библиотеки yfinance и без
  numpy/pandas). Тикер `GC=F` (фьючерс на золото COMEX — надёжнее внутри-
  дневные данные, чем спотовый `XAUUSD=X`). Ограничение Yahoo: часовые данные
  доступны только за последние ~60 дней — для EMA200 на H4 (нужно ~200×4ч
  ≈ 33+ дня истории) это впритык достаточно, но не с большим запасом.
- **OANDA demo** (`DATA_SOURCE=oanda`) — нужен бесплатный демо-счёт
  (https://www.oanda.com/demo-account/), но данные брокерские, без разрывов,
  H4 отдаётся напрямую (не собирается из H1), история практически не
  ограничена. Рекомендую перейти на этот источник, если увидите в логах
  мало баров или бот подозрительно долго "молчит".

Бот каждые `POLL_SECONDS` (по умолчанию 60) скачивает свежие свечи, прогоняет
через `strategy.py` (прямой порт логики Pine-индикатора) и, если появился
новый сетап, спрашивает Claude (`ai_filter.py`) и шлёт в Telegram
(`telegram_notify.py`).

### Установка

```bash
cd xauusd_signal_system/python_bot
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r ../requirements.txt
cp .env.example .env             # заполните TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID,
                                  # ANTHROPIC_API_KEY (остальное можно оставить по умолчанию)
python main.py
```

### Telegram-бот

1. В Telegram напишите `@BotFather` → `/newbot` → получите токен вида
   `123456:ABC-DEF...` → это `TELEGRAM_BOT_TOKEN`.
2. Напишите своему новому боту любое сообщение (иначе он не сможет писать вам).
3. Откройте `https://api.telegram.org/bot<TOKEN>/getUpdates` в браузере после
   того, как написали боту — в JSON будет `"chat":{"id": ЧИСЛО, ...}` — это
   `TELEGRAM_CHAT_ID`.

### Запуск 24/7

`python main.py` — обычный бесконечный цикл в терминале. Чтобы бот работал
постоянно, а не только пока открыт терминал у вас на компьютере:

- на VPS/сервере: `nohup python main.py &` или systemd-сервис, или `screen`/`tmux`;
- локально для теста: просто держите терминал открытым.

Каждый сетап (подтверждённый и отклонённый Claude) пишется в
`signals_log.jsonl` — раз в неделю (аналог "Блока 12 — что делать дальше")
удобно смотреть по нему статистику и вручную сверять исходы (TP/SL) для
честной оценки винрейта.

### Если сигналов долго нет

Смотрите лог — там на каждом опросе печатается количество загруженных
H4/H1/M15 баров. Если баров подозрительно мало (например H1 < 205 — не
хватает для EMA200), это проблема источника данных, а не логики сигналов —
попробуйте `DATA_SOURCE=oanda` или уменьшите `ema_period` в
`StrategyParams` (в `strategy.py`) для теста.

### Бэктест на истории из MT5 (честный винрейт, не предположения)

Claude API — это не система машинного обучения: "скормить" ему 3 года
котировок и получить модель, которая "поняла как работает золото", не
получится — так LLM не работают. Но есть честный способ узнать, как система
вела бы себя на истории — прогнать ровно ту же логику (`strategy.py`, без
переписывания) по 3 годам реальных цен и посчитать статистику.

1. В MT5: **View → History Center**, выберите XAUUSD, таймфрейм **M15**,
   скачайте максимум доступной истории (жмите "Download"/"Загрузить" пока
   не упрётся в начало данных — обычно можно получить несколько лет).
2. Правой кнопкой по списку баров → **Export** → сохраните `.csv`.
3. Запустите:
   ```bash
   python3 backtest.py --csv XAUUSD_M15.csv
   # для быстрой проверки на куске истории перед полным прогоном:
   python3 backtest.py --csv XAUUSD_M15.csv --start 2024-01-01 --end 2024-03-01
   ```
   На 3 годах M15-данных прогон может занять несколько минут — использует
   ту же `XAUStrategy.evaluate()`, что и живой бот, поэтому результат
   отражает реальное поведение бота, а не отдельную "тестовую" копию логики.
4. В консоли — Win Rate, кол-во сделок в день, разбивка по направлению и
   типу сетапа. Полный список сделок — в `backtest_trades.csv`.

### ИИ-разбор статистики (осмысленное применение Claude, не "самообучение")

```bash
python3 ai_review.py --source backtest_trades.csv
# или разбор уже накопленного живого журнала бота:
python3 ai_review.py --source signals_log.jsonl
```

Claude читает посчитанную статистику (не сырые котировки) и пишет анализ +
конкретные предложения, какие параметры `StrategyParams` попробовать
подкрутить и почему — сохраняется в `ai_review_report.md`. Это советник по
цифрам, а не автономно обучающийся трейдер: решение и повторный бэктест
после правки — всегда за вами.

### Несколько инструментов параллельно (частота без потери качества)

На реальных 3.5 годах XAUUSD подбор параметров упёрся в потолок ~0.2-0.5
сделок/день при сохранении реального edge — дальнейшее ослабление фильтров
(шире зона, короче кулдаун, другой таймфрейм входа) только портит
качество, не даёт честной частоты. Вместо этого — диверсификация: та же
самая логика и тот же фильтр качества применяются **параллельно к
нескольким инструментам**, каждый со своим независимым состоянием.

```
INSTRUMENTS=XAUUSD,EURUSD,GBPUSD,USDJPY,AUDUSD
```

Список поддерживаемых меток — в `instruments.py` (`REGISTRY`). Бот в
`main.py` создаёт отдельный `XAUStrategy` на каждый инструмент — сигналы,
кулдаун и состояние пробоя/ретеста не пересекаются между инструментами.

⚠️ Пороги "в пунктах" (`sr_zone_pts`, `breakout_buf_pts`, `pattern_tol_pts`)
и остальные настройки подобраны бэктестом **только для XAUUSD**. Для новой
пары пороги в тех же абсолютных пунктах могут оказаться неадекватны её
масштабу цены. **Прежде чем доверять сигналам по новому инструменту
деньгами — прогоните `backtest.py` на его собственной истории M15 из MT5**,
как это делалось для золота, и при необходимости подберите свой набор
`StrategyParams` (через `--sr-zone-pts`, `--pin-bar-ratio` и т.д. — см.
`backtest.py --help`, дополнительные флаги можно добавить по аналогии).

### Риск-менеджмент и недельная статистика (`risk_manager.py`)

По умолчанию бот теперь использует лучшую найденную бэктестом связку
(RR=2.5, кулдаун 3 бара, блокировка входов в дни FOMC — 300 сделок за 3.5
года, +0.272R/сделку) и добавляет три вещи поверх сигналов:

1. **Лот под реальный риск** — вместо угадывания лота руками, бот считает
   его от `ACCOUNT_BALANCE` и `RISK_PCT` (% от баланса) на КАЖДУЮ
   конкретную сделку (SL у ATR-based стратегии не фиксированный). Если при
   минимальном лоте (0.01 = 1 унция) риск всё равно выходит больше
   целевого — бот пропускает сигнал (значит депозит физически мал для
   этой сделки, честнее не форсировать её).
2. **Лимит сигналов в день** (`MAX_TRADES_PER_DAY`, по умолчанию 3) —
   защита от переторговли. На практике реальная частота сигналов на одном
   золоте — **~0.2-0.5/день** (1 сделка раз в 2-5 дней), так что этот
   лимит почти никогда не станет узким местом сам по себе; чтобы
   регулярно получать 2-3 сигнала в день — нужно несколько инструментов
   параллельно (см. выше).
3. **Недельный лимит просадки** (`WEEKLY_LOSS_LIMIT_R`, по умолчанию -6R)
   — бот отслеживает исход каждого отправленного сигнала (проверяет
   последующие свечи на TP/SL) и присылает уведомление о закрытии сделки
   с накопленным R за неделю. Если просадка за неделю доходит до лимита —
   новые сигналы ставятся на паузу до понедельника.

**Честно про "баланс должен расти каждую неделю"**: на бэктесте (300
сделок, тот же RR=2.5 конфиг) только **52.5% календарных недель со
сделками закрылись в плюс** — при экспектанси +0.272R/сделку это
нормально, положительный результат гарантирован на дистанции месяцев
(закон больших чисел), а не к каждой пятнице. Недельный лимит просадки
не делает отдельную неделю прибыльнее — он защищает депозит, пока едет
статистически нормальная полоса неудач.

## Вариант Б: TradingView Pine + webhook_relay.py (нужен платный план)

### 1. Настройка Pine-индикатора

1. Откройте `XAUUSD_TA_Master_v6.pine`, скопируйте код в Pine Editor на
   TradingView (график XAUUSD, таймфрейм M15 рекомендуется).
2. В настройках индикатора (группа "АЛЕРТ / ИНТЕГРАЦИЯ") задайте свой
   **Секрет вебхука** — любую случайную строку. Она же пойдёт в `.env`
   как `WEBHOOK_SECRET`.
3. Создайте алерт на индикатор целиком (Any alert() function call), чтобы
   срабатывали и LONG, и SHORT алерты с их JSON-сообщениями.
4. В поле Webhook URL укажите публичный адрес вашего сервиса:
   `https://ваш-домен/webhook`.
5. ⚠️ Алерты на вебхук требуют платного плана TradingView (Essential и
   выше, ~$10-15/мес) — на бесплатном Basic это не работает.

### 2. Запуск сервиса

```bash
cd xauusd_signal_system
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python webhook_relay.py
```

По умолчанию слушает `http://0.0.0.0:5000/webhook`.

### 3. Публичный доступ

- Для теста: `ngrok http 5000` → используйте выданный `https://...ngrok...`
  URL в настройках алерта TradingView.
- Для постоянной работы: Render.com, Railway.app, Fly.io, обычный VPS +
  nginx/Caddy — сервис должен работать 24/7.

### 4. Проверка без TradingView

```bash
curl -X POST http://localhost:5000/webhook \
  -H "Content-Type: application/json" \
  -d '{"secret":"REPLACE_ME","symbol":"XAUUSD","dir":"LONG","setup":"Пробой+Ретест","entry":3345.2,"sl":3335.2,"tp":3365.2,"trend":"UP","volRatio":1.5,"volOK":true,"pattern":"нет","bonus":2}'
```
